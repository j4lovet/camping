# 연곡해변캠핑장 A/B사이트 자동 감시

연곡해변캠핑장(강릉시도시관광개발공사)의 **A/B구역 전체 또는 지정한 자리 중 한 자리**를 감시하다가, 열리거나 취소로 비면 **"다음 단계"까지** 자동으로 누르고 사람이 마무리하게 만든 도구입니다.

## 0. 텔레그램 봇 만들기 · 연동 (처음 한 번, 약 10분)

빈자리 알림을 폰으로 받고, 폰에서 `시작`/`중지`로 켜고 끄려면 **본인 텔레그램 봇**이 필요합니다. (건너뛰어도 감시는 되고, 알림이 컴퓨터 화면에만 뜹니다.)
봇은 **프로그램마다 따로** 만드세요. 갯골과 연곡을 둘 다 쓰면 봇이 2개 필요합니다. (같은 봇을 두 곳에서 쓰면 서로 메시지를 빼앗아 둘 다 안 됩니다.)

### A. 텔레그램 설치 · 가입 (폰)
1. 폰 앱스토어(아이폰) / 플레이스토어(안드로이드)에서 **Telegram**(파란 종이비행기 아이콘)을 설치합니다.
2. 앱을 열고 **전화번호**를 입력 → 문자(또는 텔레그램 앱)로 온 **인증번호**를 입력 → 이름을 정하면 가입 완료. 알림을 받을 기기는 **폰**을 권장합니다. (PC용 텔레그램은 없어도 됩니다.)

### B. 봇 만들기 (폰 텔레그램에서)
3. 맨 위 검색창에 `BotFather` 를 입력하고, 이름 옆에 **파란 체크(✔)** 가 있는 공식 계정(@BotFather)을 엽니다. 하단의 **시작(Start)** 을 누릅니다.
4. `/newbot` 을 입력해서 보냅니다.
5. 봇의 **이름**을 묻습니다. 아무거나 정합니다. 예: `아빠캠핑`
6. 봇의 **아이디(username)** 를 묻습니다. 영어·숫자·밑줄(_)만 가능하고 **반드시 `bot`으로 끝나야** 합니다. 예: `papa_camping_bot` (이미 있는 이름이면 다른 걸로 바꿔 다시 입력)
7. 성공하면 긴 메시지가 오고, 그 안에 `1234567890:AAH....` 처럼 생긴 **토큰**이 있습니다. 길게 눌러 **복사**만 해두세요.
   - ⚠️ 토큰은 비밀번호입니다. 코덱스에게 알려주는 건 괜찮지만, 카톡/문자로 보내거나 화면 캡처해서 남에게 보여주지 마세요. 실수로 노출했다면 BotFather에 `/revoke` 를 보내 새 토큰을 받으세요.
8. 방금 만든 봇을 엽니다(7번 메시지의 `t.me/봇아이디` 링크를 누르면 됩니다). **시작(Start)** 을 누르거나 `/start` 를 보냅니다. ← **이걸 안 하면 연동이 안 됩니다.**

### C. 컴퓨터와 연결하기
9. 먼저 `Start Camping.bat` 로 설치를 한 번 끝내 둡니다. (설치 중 "텔레그램을 설정할까요? (y/N)" 이 나오면 `y` 를 누르고 아래 11번부터 따라 하면 됩니다.)
10. 따로 하려면: 이 폴더를 열고 **위쪽 주소창을 클릭 → `cmd` 입력 → Enter** 로 검은 창을 연 뒤 아래를 입력합니다.
    ```
    .camping-venv\Scripts\python.exe telegram_setup.py
    ```
11. 안내에 따라 진행합니다.
    - (이미 설정이 있다고 "교체할까요? YES" 가 나오면 `YES` 입력. 다른 설정은 지워지지 않습니다.)
    - **봇 토큰**: 7번에서 복사한 걸 붙여넣고 Enter. 검은 창에서는 **마우스 오른쪽 클릭 = 붙여넣기**입니다. **화면에 아무것도 안 보이는 게 정상**입니다.
    - `확인된 봇: @봇아이디` 가 나오면 맞는지 보고, 8번을 했는지 확인한 뒤 Enter.
    - 대화 목록이 나오면 **본인 이름 앞의 번호**(보통 `1`)를 입력합니다.
    - `테스트 알림을 보낼까요?` → `YES`
    - 폰 텔레그램에 "연결 테스트입니다" 메시지가 오면 → `YES` 로 저장.
**11-B. [더 쉬운 방법] 코덱스(AI)에게 맡기기** — 7번에서 복사한 토큰을 코덱스 채팅에 붙여넣고 "이 토큰으로 연결해줘"라고 하면 코덱스가 아래를 대신 실행합니다. (8번 `/start`를 먼저 보냈어야 합니다. 성공하면 폰에 "연결 테스트" 메시지가 옵니다.)
```
.camping-venv\Scripts\python.exe telegram_setup.py --token 토큰전체
```
코덱스에게 알려주는 건 괜찮지만, 카톡 등 다른 사람에게는 보내지 마세요.

12. (선택) 폰으로 켜고 끄기: 같은 검은 창에서
    ```
    .camping-venv\Scripts\python.exe install_remote.py
    ```
    그다음 폰에서 **내 봇**에 `도움말` 을 보내 답이 오면 성공입니다. `시작` / `중지` / `상태` 도 보내 보세요. (컴퓨터가 켜져 있어야 합니다.)
13. (선택) 아침 알림: `.camping-venv\Scripts\python.exe install_reminder.py`

### D. 안 될 때
| 증상 | 해결 |
|---|---|
| "개인 메시지가 없습니다" | 8번(`/start`)을 안 한 겁니다. 봇에 `/start` 를 보내고 다시 실행 |
| "토큰 형식을 확인하세요" | 토큰 전체(숫자:영문)를 다시 복사. 앞뒤 공백/따옴표 없이 |
| 409 오류 | 같은 봇을 다른 프로그램이 쓰는 중. 이 프로그램용 **새 봇**을 만드세요 |
| 테스트 메시지가 안 옴 | 봇 대화창에서 `/start` 를 보냈는지, 폰 인터넷/알림 설정 확인 |
| 토큰을 남에게 보여줬다 | BotFather에 `/revoke` → 새 토큰으로 위 11번부터 다시 |

## 1. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 사이트 | https://camping.gtdc.or.kr/pub/reserv.do?tmonth=YYYYMM (로그인 불필요) |
| 노리는 조건 | **토요일 1박 · A구역 중 한 자리 · 2명**, 오늘부터 최대 45일 앞까지 |
| 오픈 | **날짜마다 한 달 전 같은 날짜 10:00** (예: 12/5 → 11/5 10:00). 없는 날짜는 다음 달로 넘김(12/31은 12/1 오픈) |
| 자동으로 하는 일 | 달력에서 설정한 A/B구역 조회 → 우선순위에 맞는 빈자리 한 곳 선택 → 인원 설정 → [다음 단계] → 인증/정보입력 화면에서 정지 + 텔레그램 알림 |
| 사람이 하는 일 | 인증 숫자(캡차), 이름·전화번호·약관, 최종 예약/결제 |
| 절대 안 하는 일 | 캡차 풀기, 대기열/접근 제한 우회, 비활성 버튼 강제 클릭, 숨은 API 호출 |

## 2. 동작 흐름 (`camping_watch.py`)

1. 이번 달 달력 페이지를 열고 Enter(또는 `--auto-start`)로 시작, "감시 시작" 알림.
2. 한 바퀴마다 대상 날짜(설정 요일)를 차례로 `inspect(day)`:
   - 월 이동 → 해당 날짜의 A(구역 코드 1)/B(구역 코드 2) 버튼 확인 → `NOT_OPEN`(버튼 없음) / `ZONE_SOLD_OUT`(구역 마감) / 선택 후 `SITE_SOLD_OUT`(대상 자리 마감) / `AVAILABLE`. 혼합 지정은 양쪽 구역 후보의 우선순위를 비교하고 선택할 구역 화면으로 돌아간다.
   - 입실·퇴실·설정한 박수, 화면의 A/B구역 시설명과 실제 선택 ID를 검증. 2박은 날짜변경 달력에서 입실일·퇴실일을 클릭해 기간 전체의 빈자리를 다시 조회. 시설 번호로 내부 ID를 계산하지 않음.
3. `AVAILABLE`이면 `attempt()`: A/B구역 한 자리 단일 선택 확인 → 인원 설정(`-` 버튼) → 날짜 재검증 → 상태에 `active` 기록 → [다음 단계] 클릭.
4. 결과 판별 (`handoff_phase`): `CAPTCHA_REQUIRED`(인증 필요) / `HELD`(임시점유 타이머 확인) / `FORM_READY`(정보입력) / `REVIEW_REQUIRED`(확인 불가) → 텔레그램 알림 후 **감시 정지, 창 유지**.
5. 인증 화면에서 사람이 숫자를 입력해 통과하면 `HELD/FORM_READY`로 다시 알림.
6. 접근 제한·안내 팝업·캡차가 감시 중 나오면 우회하지 않고 멈춤.

## 3. 확인 주기

| 시각 | 간격 |
|---|---|
| 평소 (취소표 대비) | 15초 |
| 날짜가 열리는 시각(10:00) 10초 전 ~ 60초 후 | 1초 |
| 그중 09:59:58 ~ 10:00:20 (2초 전 ~ 20초 후) | 0.1초 대기 (화면 처리 시간이 추가됨) |

09:59:58~10:00:20에는 오늘 열리는 대상 날짜가 매진으로 바뀌어도 0.1초 대기를 유지함. 그 밖의 빠른 확인 구간에서는 아직 안 열린(`NOT_OPEN`) 날짜만 1초 대기. 해당 구간에 프로그램을 처음 시작해도 적용됨. 자리 선택 후 인증/정보입력 중단 동작은 그대로 유지. `--open-only`는 오늘 열리는 날짜만 감시.

## 4. 설정 (`camping_settings.json`)

```json
{ "site": "A*", "weekdays": [5], "reminder_weekdays": [5], "nights": 1, "headcount": 2,
  "max_lookahead_days": 45, "poll_seconds": 15, "open_time": "10:00",
  "fast_poll_seconds": 1, "fast_before_seconds": 10, "fast_after_seconds": 60,
  "burst_poll_seconds": 0.1, "burst_before_seconds": 2, "burst_after_seconds": 2,
  "stop_at_customer_form": true }
```
- `weekdays`/`headcount`/`max_lookahead_days`는 자유롭게 변경 가능.
- **site는 "A*", "B*", "AB*"(구역 전체), "B220"(한 자리), 또는 ["B220", "A135"](지정 번호 목록)**. 지원 번호는 A101~A153, B201~B246이며 실제 화면의 선택 ID를 확인한다. 날짜·숙박 조건은 모든 구역에서 동일하다. **nights는 1 또는 2**.
- `설정_보기_수정.bat`의 **8번은 A/B사이트 전체·번호·범위 선택**. 1=A전체, 5=B전체, 6=A·B전체. 2=특정 번호만, 3=지정 자리 뒤 해당 구역 전체, 4=지정 자리 → `site_ranges` 범위 → 해당 구역 전체. `B220 A135`, `B210~B230 A110~A148`처럼 두 구역을 함께 지정할 수 있다. `fallback_all_sites`는 지정 자리·범위가 포함한 구역 안에서만 적용한다. A/B 혼합 시 두 구역을 조회하고 우선순위가 높은 한 자리만 선택한다. 변경 후 감시를 재시작할 것.
- `설정_보기_수정.bat`의 **6번은 입실 날짜 지정/해제**, **7번은 1박/2박 변경**. 예: 입실 날짜 `2026-11-20 2026-11-27`, 2박이면 11/20~22 또는 11/27~29 중 먼저 가능한 한 건만 진행.
- `checkin_dates: ["2026-11-20", "2026-11-27"]`처럼 날짜를 지정하면 요일 조건을 대신함. `[]`는 기존 요일 조건 사용. 날짜는 오늘~max_lookahead_days 안에서만 조회하고 지난 날짜는 제외. 대상이 없어도 다른 요일로 대체하지 않음. 요일을 변경하면 날짜 지정은 해제됨.
- 지정일은 오픈 시간 빠른 조회와 9:30 알림에도 동일하게 적용. 모든 지정일에 같은 숙박 일수를 적용함. 정보입력 화면에서도 사이트·입실일·퇴실일·박수가 맞아야 임시점유/정보입력 확인으로 알림.

## 7. 폰 리모컨 · 알림

- 본인 텔레그램 **개인 대화**에서만 동작(그 외 대화·봇 메시지는 무시). `시작` / `오픈`(오늘 열리는 날짜만) / `중지` / `상태` / `도움말`.
- 실행 중인 감시가 있으면 중복 시작을 거절. 현재 실행에 예약 진행 기록(`active`)이 있으면 원격 중지를 거절. 실행이 꺼져 있으면 이전 기록만으로 시작을 막지 않음.
- 컴퓨터가 켜져 있어야 동작(잠자기/덮개 닫힘 = 멈춤). 알림 프로그램(09:30)도 맥에서 도는 것이라 그 시각에 깨어 있어야 제때 옴.

## 8. 오류 · 종료 시 주의

- 중복 실행은 운영체제의 `camping.lock` 잠금으로 차단. 잠금 파일이 남아 있어도 프로세스가 종료되면 잠금은 해제됨. 새 실행이 잠금을 얻으면 이전 `active` 기록을 `data/state_history/`에 원본 백업하고 진행 표시만 초기화. 비정상 종료 후에도 같은 방식으로 복구함. 체험 기록도 잠금을 얻은 뒤 복구하며 무조건 삭제하지 않음.
- 로컬 진행 기록은 실제 예약 접수 여부를 의미하지 않음. 복구는 사이트 예약·점유를 취소하지 않으며, 예약 내역 확인은 사용자가 직접 해야 함.
- Telegram 409: 같은 봇을 다른 프로그램이 getUpdates로 쓰는 중 → 봇을 분리(갯골은 별도 봇 사용).
- 브라우저 창을 닫으면 정상 종료(예약 진행 기록은 보존).
